## Feito
- **Camada de intake** (iniciada na transferência de contexto, agora consolidada e testada):
  - `src/schemas/instruction_v1.schema.json` — JSON Schema Draft 7 completo (o contrato). Trocado `comment` por `$comment` (idiomático).
  - `src/core/instruction_parser.py` — carrega YAML/JSON (com fallback de encoding utf-8→cp1252), não valida.
  - `src/core/instruction_validator.py` — valida contra schema + `format_version`; acumula todos os erros com caminho do campo.
- **13 estratégias** implementadas (padrão Strategy, DEC-002):
  - Python via libcst: `replace_function`, `replace_method`, `replace_class` — substituição por nome com escopo léxico correto (método na classe certa, função de módulo não confundida com método homônimo) e preservação de indentação/linhas em branco.
  - Texto universal via `re`: `insert_after_pattern`, `insert_before_pattern`, `replace_line_pattern`, `replace_context_block` (janela de contexto por âncoras literais).
  - Markdown: `replace_section` (seção delimitada por heading de nível ≤).
  - JSON via jmespath (leitura) + navegador próprio (escrita): `set_json_path`, `append_json_array`, `delete_json_path`.
  - Arquivo inteiro: `replace_file`, `create_file` (DEC-008).
- **Orquestração**:
  - `src/core/file_locator.py` — resolve relative/absolute, guarda de contenção (caminho relativo não escapa da raiz), checa existência conforme a estratégia.
  - `src/core/backup_manager.py` — backup timestampado espelhando a estrutura de pastas; `restore_all()` e `rollback_session(root, timestamp)` para o CLI.
  - `src/core/diff_renderer.py` — unified diff colorido (colorama, degradação graciosa).
  - `src/core/patch_engine.py` — aplica em sequência (reparse implícito entre modificações do mesmo arquivo), transação com **rollback atômico** em falha, dry-run, precedência de settings.
  - `src/__main__.py` — CLI (`validate`, `apply` com prévia+confirmação, `rollback`).
- **Estruturais**: `pyproject.toml` (pytest/ruff/black), `requirements.txt` (núcleo sem Qt), `requirements-gui.txt`, `requirements-dev.txt`, `.gitignore`, `README.md`.
- **Testes**: 42 testes (`test_instruction_parser`, `test_strategies`, `test_patch_engine`) — todos verdes. Cobrem escopo Python, limites de seção markdown, contexto, ocorrência de regex, JSON set/append/delete, guarda de contenção, dry-run, rollback atômico e roundtrip de rollback por timestamp.
- **Smoke test manual** ponta a ponta (apply + rollback) validado via `python -m src` em projeto-fixture com os 4 tipos de arquivo.

## Decisões
- **DEC-008:** Estratégias `create_file` e `replace_file` — unificam os dois modos do fluxo (criar projeto do zero OU patch cirúrgico) no mesmo schema.
- **DEC-009:** Removido o campo `location.type`; a `strategy` é a fonte única de como interpretar `location`. Papéis Python explícitos: `replace_function` (módulo) / `replace_method` (classe, `class_name` obrigatório) / `replace_class`. Interface da estratégia simplificada para um único `apply()` (localiza+aplica); a pré-checagem de confiança da GUI (F2) virá do dry-run por modificação.
- **DEC-010:** Independência de linguagem via janela de contexto/regex (operam sobre texto cru); libcst (Python) e jmespath (JSON) são reforços opcionais. `requirements` dividido em núcleo (sem Qt) / gui / dev, alinhado à meta de core como biblioteca pura (F4).

## Aprendizados / armadilhas
- libcst recalcula a indentação ao renderizar o nó dentro do bloco pai, mas o nó de substituição traz suas próprias `leading_lines` — é preciso copiar `leading_lines` do nó original para preservar as linhas em branco que separavam a definição da vizinha.
- Rastrear o escopo léxico (pilha de classe/função) é essencial para não confundir um método com uma função de módulo de mesmo nome.
- Estilo de newline: ler o arquivo em modo texto normaliza `\r\n`→`\n`; detectamos o estilo pelos bytes crus e o reaplicamos ao gravar, evitando que arquivos Windows virem LF silenciosamente.
- jmespath é só de consulta (não escreve); set/append/delete exigem navegador de caminho próprio.
